# 0016 · 画布整理：类别、摆放、框、连线与工作文档

状态：已实现（2026-10-30）

日期：2026-10-29

基于 [0003](0003-core-contracts.md)、[0006](0006-web-ui.md)、[0007](0007-generation-providers.md) 与 [0010](0010-workspaces-without-canvas-binding.md)。来源：维护者 2026-10-29 提交的体验问题清单（画布与工作管理部分），草图见 `优化项/排列优化示例.png`。

## 背景

多个 Agent 同时往一块画布写内容后，画布很快变乱：

1. 生成的结果很容易重叠。Agent 建节点时自己写坐标，只有「向右延伸」走了 `freePosition`。
2. 内容框（Frame）和里面的节点没有绑定：框里的节点能被单独拖出去，框也不会随内容长大。
3. 分镜、代码这类文本没有连线指向由它产出的结果；现在只有生成时的参考输入和来源有线。
4. 用户改了代码之后，没有手动渲染的入口。
5. Agent 之间用 md 传话，这些 md 也成了画布上的文本节点，淹没了真正的产物。
6. 内容没有类别，无法按「人物、场景、道具、镜头」自动整理。

草图的意思：按类别分区（每区一个框），人物、场景里的节点连线指向镜头里的节点；框里的节点整齐排列。

## 决定

### 1. 类别

`NodeView` 与 `canvas.apply` 的节点创建 / 更新增加可空字段 `category: string | null`（最长 20 字，去首尾空白）。类别是自由文本，界面与 Agent 提示词推荐一组常用值：**人物、场景、道具、镜头、分镜、文案、其他**，但不做枚举，项目可以有自己的类别。

- 用户可在节点右键菜单「设置类别…」修改；Agent 通过 `canvas_*` 工具创建或更新节点时可带上 `category`。
- 旧节点为 `null`，整理时归入「未分类」。
- 镜头节点（一个节点 = 一个镜头）本 RFC 不做，维护者确认不着急：它的类别暂用「镜头」；专用节点类型以后单独设计。
- 已确认（2026-10-29）：类别是自由文本，不做枚举。

### 2. 摆放：不再重叠

**服务端创建时找空位。** `canvas.apply` 的节点创建若没给位置，或给的位置与已有节点重叠，由画布服务（`placement.ts`）选位置：

- 有来源 / 参考节点时，放在它们右侧，按 `freePosition` 的间隔避开重叠；
- 有 `category` 且项目里已有同类别的框时，放进那个框的下一个空位（见 4）；
- 否则放在当前内容的右下方空白处。

Agent 显式给了位置且不重叠时尊重它；重叠时挪开。用户显式给的位置不挪。服务端决定或挪动过的位置在返回值 `placements[tempId]` 里带回，Agent 不需要再猜。同类别框放不下时，沿 `frameId` 链从内到外撑大祖先框，与创建同批撤销。

**整理画布。** 画布工具栏加「整理」按钮（带确认预览）：

- 按类别分组，每组一个竖向的框：没有对应框就新建，框标题为类别名；框内节点按网格排列、宽度统一；
- 组与组之间从左到右排列，使有连线的上游（人物、场景、道具）在左、下游（镜头）在右，尽量减少连线交叉；
- 用户手动调整过的框大小保留，只调整框内节点与超出的框；
- 一次整理是一个可撤销批次（沿用现有撤销 / 重做），只生成 `node.layout` / `frame.*` 操作，不改内容与类别；
- 选中若干节点时只整理选中的部分；此时保留未选节点与已有框的位置优先于「上游一定在左」。
- 一次整理最多 200 个操作，超过时提示缩小选择。

整理是用户主动触发的动作，不自动运行，避免打乱用户刚摆好的位置。

### 3. 连线补全

现有连线两种：来源线（生成产物的输入）和参考线（`node.inputs`）。补全：

- **生成记录输入。** 核对结果（2026-10-30）：`generation.submit` 的 `inputs` 里每个槽位（包括文本）原本就写入 `job_inputs` 并成为来源线，没有丢失。缺线的原因是调用方只把文本放进 `prompt` 字符串、没有把文本槽位放进 `inputs`；提示词现在要求 Agent 同时提供。
- **Agent 声明关系。** 创建节点的工具增加可选 `inputs`（节点 ID 列表）并在提示词里要求：产物由某些节点得出时必须带上。写入 `node.inputs`，不新增连线种类。
- **选中高亮**（已在体验优化第一批完成）对新增的线同样生效。

### 4. 框收住节点

草图里的框是「内容区」：节点属于一个框，框是它们的边界。规则：

```
┌ 人物 ─────────┐          成员节点：
│ ┌──┐          │           · 拖动只能在框内移动，碰到边缘停住
│ │  │   ┌──┐   │           · 框随成员增减自动调整大小（有最小尺寸与内边距）
│ └──┘   │  │   │           · 新节点落进框、或拖进框，即成为成员
│        └──┘   │           · 要移出：右键「移出框」，或拖动时按住 ⌘/Ctrl 越界
└───────────────┘
```

- 成员关系继续使用现有的 `frameId`，不新增数据。界面层对成员节点加范围限制，并在成员变化后重算框大小。框只撑大、不自动缩小（契约里没有「用户手动调整过尺寸」的标记，因此一律保留现有尺寸）。
- 界面发起的自动撑大是一个独立的撤销条目；刷新页面后不保证与触发它的移动合成一步撤销。若要严格事务化，需改由画布核心在原事务里处理（暂不做）。
- 嵌套框：内层框也是外层框的成员，规则相同。
- 框本身整体移动时成员一起移动（现有行为，不变）。
- 删除框仍然保留成员节点（0010 的既有规则）。

已确认（2026-10-29）：成员只能在框内移动，移出用 ⌘/Ctrl 拖动或右键「移出框」；框随成员自动撑大。

### 5. 代码节点与手动渲染

文本节点增加可选 `format: 'plain' | 'markdown' | 'code'`，`code` 节点以等宽字体显示并带语言标记（先支持 `html`）。

- 代码节点上显示「渲染」按钮：以节点内容为输入、`render/html` 服务提交一次生成，产物写回该节点关联的结果节点（没有则新建一个视频 / 图片节点并连来源线）；已有结果时作为新版本，保留版本历史。
- 渲染走现有的生成任务与幂等（`requestId`），`render` 不计费也不受每日上限；失败时在节点上显示问题并可重试。
- 用户编辑代码不会自动重新渲染；节点显示「代码已修改，未渲染」的小提示，直到再次渲染。

核对结果（2026-10-30）：`render/html` 只产出视频，把 `inputs` 里第一个文本槽位的内容当作完整 HTML，不读 `prompt`。首次渲染提交 `{ kind: 'video', provider: 'render', model: 'html', prompt: '', inputs: [代码主槽位与当前修订] }`，不指定目标即新建结果并连来源线；再次渲染以结果视频主槽位为目标（带 `expectedRevision`），作为新版本保留历史。代码与结果的关联由结果主槽位的 `source.inputNodeIds` 表示，不需要新字段。浏览器只记本机渲染过的修订号，其他浏览器首次打开会保守显示「未渲染」。

### 6. 工作文档与产物区分

Agent 之间的 md 传话进画布，产生大量干扰。两层处理：

- **治本：提示词。** Agent 说明里明确：交付物才写画布；沟通、进度、计划写在回复里，或用 `work_report` / 回复；子工作区的报告走 `work_report`，不要建「报告」文本节点。
- **兜底：节点用途。** 节点增加 `purpose: 'artifact' | 'working'`，默认 `artifact`。`working` 表示工作文档：画布上默认隐藏，工具栏加「显示工作文档」开关（保存在浏览器偏好里）；隐藏的节点不参与整理与重叠检测，但仍可被 Agent 读取和被连线引用。Agent 与用户都可设置；用户可从节点菜单「标为工作文档」。

不做自动识别（例如按文件名或内容猜哪些是传话 md），避免误伤。

### 7. 快捷键介绍

维护者 2026-10-29 提出：画布上的快捷键用户不知道。

- **空画布时显示在画布正中**：画布没有任何节点时，中间显示「画布快捷键」，列出最常用的 6–8 项：平移与缩放、框选、撤销 / 重做、复制 / 粘贴 / 创建副本、删除、全屏预览（Space）、切换画布与看板（⌘⇧B）、收起会话面板（⌘\\）。它是空状态的一部分，不是弹窗：不挡操作、不需要关闭，点击和拖入文件照常落到画布上。
- 画布上有了内容就不再显示；内容全部删掉后又回到空状态，再次显示。不记录「看过」，不用 `localStorage`。
- **随时可看**：画布右下角缩放控件旁加一个「?」按钮，或在画布上按 `?`（输入框里打字时不触发），打开完整的快捷键面板，按「画布 / 节点 / 会话 / 视图」分组。
- 按系统显示修饰键：macOS 显示 ⌘，其他系统显示 Ctrl。
- **一份清单**：快捷键列表定义在 `canvas-ui` 的一个模块里，空状态和完整面板都从它渲染；README 的快捷键表与它保持一致，有单测核对两边没有漏项。
- 完整面板可用 Esc 关闭，焦点回到画布；出现动画遵守 `prefers-reduced-motion`。

## 契约变化（先于实现）

- `packages/protocol`：`NodeView` 增加 `category`、`purpose`，文本槽位增加 `format`；`canvas.apply` 的节点创建 / 更新操作带上这三项与 `inputs`；`canvas.layout`（整理预览与应用）是否单独成方法或复用 `node.layout` 批次，在实现前由我定；契约测试同步。
- storage：space 迁移新增列（`nodes.category`、`nodes.purpose`，文本槽位 `format`），旧数据补默认值；`db:generate` 生成，不手写。
- `vis` 工具（MCP）与 Agent 提示词（`prompt.ts`）同步；Agent 可见的方法说明更新。

## 实施拆分

1. **契约与核心**（我）：协议、迁移、画布服务的摆放（`placement.ts`）、`inputs` 与生成输入记录。
2. **画布界面**：框收住节点与自动撑大、整理按钮与预览、类别菜单、代码节点与渲染按钮、工作文档开关、空画布快捷键与完整面板。
3. **Agent 侧**：提示词与工具参数；真实 Agent 的行为验证（需要维护者批准）。

第 2、3 项依赖第 1 项的契约，可先合并类型定义再并行。

## 不做

- 自动整理（只做用户触发的整理）。
- 专用镜头节点（单独设计，类别「镜头」是它的基础）。
- 按内容自动识别工作文档、按内容自动分类。
- 代码节点支持 html 以外的语言渲染。

## Real-use tidy correction (2026-11-05)

The tidy plan now includes frames left with no members, including frames that were already empty. Category targets remain. The preview lists candidate frame titles under a checked-by-default removal option; unchecking it keeps those frames. Selected-only tidy considers only frames whose members it actually moved, preserving unrelated empty frames and any frame with unselected or working descendants. Frame-only `node.delete` operations follow placement in the same undoable `canvas.apply` batch; member nodes and their content are never deleted.
