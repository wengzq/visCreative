# 0011 · 删除项目与「最近删除」

状态：已实现并验证（2026-10-29）

日期：2026-10-29

基于 [0008](0008-projects-and-workspaces.md)、[0009](0009-work-items-and-board.md)（工作项删除）与 [0010](0010-workspaces-without-canvas-binding.md)。

## 背景

项目（空间）现在只有 `space.create` 和 `space.list`，建了就一直在列表里，无法删除。项目里生成过的图片和视频存在应用数据（`blobs/`）里，不在项目目录中，误删就要重新花钱生成，所以删除要能反悔。

这次不做「释放」：不加自动或手动关闭项目。删除时项目会被关闭，它的 Agent 进程、生成轮询和数据库连接随之退出；已删除的项目之后不再被任何全局视图打开。

## 决定

**删除 = 停止一切 + 移到「最近删除」。**数据原地保留，可以恢复；只有在「最近删除」里再点「永久删除」才删文件。删除时不动项目目录（`rootPath`，含 `assets/`、`skills/`、`workspaces/`）；永久删除时可以勾选一并删除，直接删除，不经过系统废纸篓（跨平台一致，也为以后支持 Windows 保持简单）。

## 删除

`space.deletePlan` 先读影响，确认框按结果提示；`space.delete` 执行：

1. 对项目里所有未归档的工作项做与 `work.delete` 相同的停止：停止回合、取消未结束的生成任务、清空排队、释放运行名额。不属于工作项的会话也停止当前回合。取消不等于退款：`providerCancelled: false` 的任务照实返回，界面照常提示可能仍会计费。
2. 一个 app.db 事务里给 `spaces` 写 `deletedAt`，删掉该项目在名额排队里的条目。项目内部的数据（工作项、会话、画布）**不改写**，恢复时原样回来。
3. 关闭这个项目的 SpaceHost（`close()`：释放运行时、等待会话收尾、停止生成轮询、关闭数据库），从注册表移除。
4. 广播 `events.spacesChanged`（临时通知，不进事件日志），所有窗口重新读取项目列表。

幂等按 `requestId`，记录在 app.db。删除不需要 `expectedRevision`。

删除后：

- `space.list`、项目切换、看板「全部项目」、收件箱、名额排队、启动恢复都**跳过**已删除项目，不再打开它。
- 指向它的任何 `spaceId` 请求返回 `not_found`（「项目已删除」）。Agent 令牌随会话一起失效。
- 正在看这个项目的窗口：切到列表里最近打开的另一个项目；没有项目时显示「还没有项目，请新建项目」。
- 今日生成额度仍然计入（账本在 app.db，与项目是否删除无关）。用量面板的任务明细不打开已删除项目，改为一行「另有 N 个任务属于已删除的项目」。

## 最近删除

设置里新增「最近删除」：列出已删除项目的名称、删除时间、项目目录，以及占用空间：「素材与历史 2.3 GB · 项目目录 850 MB」（应用数据目录与 `rootPath` 分别统计；计算在后台进行，大目录先显示「计算中…」，项目目录不存在时显示「项目目录已不存在」）。

- **恢复**（`space.restore`）：清掉 `deletedAt`，回到列表；被停止的工作项保持停止时的状态（与回收一致：进行中的变回待办，需要用户重新激活）。同名项目已存在时仍可恢复，列表里两个同名项目并存。项目目录已不存在时照常恢复，提示「项目目录已移动或无法访问」，与会话工作目录缺失的处理一致。
- **永久删除**（`space.purge`）：删除这个项目的应用数据目录（`<数据目录>/spaces/<spaceId>/`：`space.db`、`blobs/`、旧版会话工作目录等），再删掉 `spaces` 行。
  - `deleteProjectDir: true` 时同时删除项目目录 `rootPath`（递归删除，符号链接只删链接本身，不跟进）。
  - 安全检查，任一命中就拒绝删除项目目录（整次操作提前返回 `forbidden`，应用数据与项目目录均不删除，不记录 `purge_error`）：`rootPath` 是文件系统根、用户主目录、`$VIS_PROJECTS_DIR` 或默认项目根目录本身；`rootPath` 包含应用数据目录，或包含另一个项目（含已删除的）的 `rootPath` 或数据目录。
  - 旧项目的 `rootPath` 就在空间数据目录下（`.../project`，见 0008）：不勾选时先把它移出到 `<数据目录>/orphaned-projects/<spaceId>/` 再删数据目录，结果里返回新位置；勾选时一并删除。
  - 删除中途失败（文件被占用、无权限）：已删的不回滚，`spaces` 行保留并标记 `purgeFailed`，「最近删除」里显示错误，可以重试。

不做自动清理：放多久都不会被自动永久删除。

## 界面

- 项目切换菜单：每个项目一行，悬停出现 `⋯`，菜单里「删除项目…」（最后一项、红色、上方分隔线）。
- 确认框，标题「删除项目「{名称}」？」。按 `space.deletePlan` 的结果列出警告：
  - ⚠ 有 N 个 Agent 正在工作，删除会先停止它们
  - ⚠ 有 N 个生成任务未完成，会被取消（已提交的可能仍会计费）
  - ⚠ 有 N 个工作项进行中
  - ⚠ 有 N 条提问在等你回复，删除后不再处理

  正文：「项目会移到设置里的「最近删除」，可以恢复。项目目录不会被删除：」加目录路径。按钮在有回合或生成在跑时为「停止并删除」，否则为「删除」；默认焦点在「取消」，Esc 关闭。与工作项删除确认框（0009 UI §5.5）同一样式。
- 成功后提示「已删除「{名称}」，可在设置 › 最近删除中恢复」；有 `providerCancelled: false` 时再给计费提示。
- 设置对话框原名「生成服务设置」，加入「最近删除」后改名为「设置」（顶栏按钮与 ⌘, 不变）；「最近删除」的操作即时生效，这一页不显示「取消 / 保存配置」。
- 设置 › 最近删除：每行「恢复」「永久删除…」。永久删除确认框：
  - 标题「永久删除「{名称}」？」；正文「画布、历史和生成的素材（{大小}）会被删除，无法撤销。」
  - 勾选项「同时删除项目目录（{大小}）」加目录路径，**默认不勾选**；勾选后下方红字「项目目录里的所有文件都会被删除，包括你自己放进去的文件」。安全检查不通过时勾选项禁用并说明原因。
  - 按钮「永久删除」（危险色），默认焦点在「取消」。

## 协议变化

全部只允许界面调用（`callers: ui`），Agent 在能力列表与 MCP 里看不到：

- `space.deletePlan({ spaceId })` → `{ runningTurns, unfinishedJobs, workInProgress, unresolvedMessages, rootPath }`
- `space.delete({ requestId, spaceId })` → `{ spaceId, cancelledJobs: [{ jobId, providerCancelled }] }`
- `space.listDeleted({})` → `{ spaces: [{ spaceId, name, rootPath, deletedAt, rootPathExists, canDeleteProjectDir, purgeError }] }`
- `space.diskUsage({ spaceId })` → `{ dataBytes, projectDirBytes }`（`projectDirBytes` 在目录不存在时为 null）
- `space.restore({ requestId, spaceId })` → `SpaceSummary`
- `space.purge({ requestId, spaceId, deleteProjectDir? })` → `{ spaceId, projectDirDeleted, movedProjectDir? }`，只能作用于已删除的项目，否则 `invalid_transition`
- 新通知 `events.spacesChanged`（无参数），新建、删除、恢复、永久删除后发出。

## 迁移

app.db 的 `spaces` 新增可空列 `deleted_at` 与 `purge_error`（`pnpm --filter @vis/storage db:generate`）。现有项目全部为未删除。

## 实施拆分

一个 worker 即可：协议与能力测试 → studiod（删除、恢复、永久删除、注册表跳过、启动恢复跳过、用量面板）→ 界面（项目菜单、确认框、最近删除）→ e2e。

测试要点：删除正在运行的项目会停止回合、取消生成、释放名额并让排队的其他项目开始；删除后全局视图不再打开它；恢复后数据完整、工作项为待办；永久删除删掉数据目录，不勾选时项目目录完整保留（旧版位于数据目录下的 `project/` 被移出保留），勾选时删除；各条安全检查拒绝删除危险目录；删除中途失败可重试；按 `requestId` 重试不重复执行；Agent 看不到这些方法。

## 实施说明

- 「不改写项目内部数据」指不归档或移除工作项、会话、画布与历史。停止必需的回合、生成终态、令牌失效与会话队列暂停照常持久化；恢复时清除名额排队，进行中工作项回到待办，不自动重启执行。
- 删除、永久删除的操作意图在 app.db 中先记录再执行；相同 requestId 重试继续或重放，不同参数返回冲突。永久删除中断留下错误标记，部分数据可能已丢失，因此只能重试永久删除，不能恢复。
- 目录安全检查失败整次操作提前返回 forbidden；应用数据和项目目录均不删除、不写 purge_error。purge_error 仅用于实际清理失败或清理中断，不用于安全预检拒绝。
- 用量账本移除对 spaces 的外键，永久删除项目后仍保留当日计数。generation.usage 增加可选 deletedProjectJobs，且无当前项目时也能查看全局用量。
- space.listDeleted 增加 canDeleteProjectDirReason（可空字符串），用于解释禁用勾选的原因。路径检查解析现存父目录与链接目标；统计和递归删除均不跟进目录树内符号链接。
- 异常的跨项目嵌套也保守保护：若项目应用数据目录本身包含另一个项目的项目目录或应用数据，永久删除提前返回 forbidden，不记录清理错误、不删除任何文件。
- 生命周期变更执行期间，新建项目返回 busy，避免另一个窗口在目录安全检查之后创建共用目录的项目。
- 最近打开顺序由界面订阅项目记录，后台看板、用量读取不改变顺序。项目目录不存在时恢复及打开不自动重建该目录。

`pnpm check` 通过（856 项测试），`pnpm build` 通过，全量浏览器 e2e 连续两轮通过（每轮 91 项）。测试仅使用假 Agent、假生成服务和临时目录；未调用真实模型或 Ark。
