# 0018 · 界面中英切换

状态：已实现（2026-10-30）

日期：2026-10-30

基于 [0006](0006-web-ui.md)（网页界面）与 [0003](0003-core-contracts.md)（错误码）。来源：维护者 2026-10-30「下一期之前要做英文版，因为最后要开源」。

## 背景

界面文案、aria-label、提示和后台报错全部写死成中文，散在三个界面包里约 1240 处（`scripts/check-i18n.mjs` 统计：画布 ~310、会话与工作 ~530、网页客户端 ~380），另有约 180 条后台 `VisError` 中文消息会原样显示给用户。开源后不懂中文的用户无法使用。

## 决定

### 1. 范围

**翻译**：三个界面包（`packages/canvas/ui`、`packages/workbench/ui`、`apps/web/src/client`）里所有给人看的文字：按钮、标题、提示、空状态、aria-label、title、确认文案、通知、日期与数字格式；以及用户在界面上会看到的后台错误。

**不翻译**：

- 用户与 Agent 写进去的数据：节点内容、类别（「人物」「场景」）、框标题、会话与工作项标题、消息正文。已经存成中文的保持中文。
- 给 Agent 看的文字：`prompt.ts` 的开发者说明、工作消息正文、`methods.ts` 的能力说明、CLI 输出。Agent 会跟着用户提问的语言回复（维护者 2026-10-30：提示词先不动，以后再说）。
- 代码注释与 RFC 保持中文（维护者 2026-10-30 选 A；开源前再评估是否翻译 RFC）。

推荐的常用类别列表（人物、场景、道具……）只是界面上的建议，跟着语言显示；用户选了哪个，就按当时显示的文字存下来。

整理时，「未分类」和「Uncategorized」都视为未分类框：优先复用标题与当前语言一致的那个，其次复用另一个，都没有才按当前语言新建；不自动改旧框标题。其他类别仍按存储的原文匹配。

像素尺寸、比例、种子、帧率这类技术数值不做千位分组，中英文都原样输出整数（例如 2048×1152）；`formatter` 只用于数量、字节、日期时间与相对时间。

### 2. 语言与切换

- 只有两种：`zh-CN` 和 `en`。
- **默认跟随浏览器**（维护者确认）：`navigator.languages` 里第一个中文（`zh`、`zh-*`）或英文（`en`、`en-*`）决定；都没有时用英文。
- 设置窗口加「通用」一节，语言三选一：跟随系统 / 中文 / English。切换立即生效，不刷新页面。
- 选择存在 `app.db` 的 `settings`（键 `ui.locale`），换浏览器也保留。为避免启动时闪一下另一种语言，网页端在 `localStorage` 记一份上次用的语言，连上 studiod 后以 `app.db` 为准。
- `<html lang>` 与页面标题跟着语言变。

### 3. 实现：不加依赖

`@vis/ui-kit` 提供（已在契约提交中实现）：

- `defineMessages(zh, en)`：每个界面包有自己的 `messages.ts`。英文词典的类型由中文词典推出，缺键或函数签名不一致时 typecheck 直接报错。值是字符串，或接收参数返回字符串的函数（插值、复数都写在函数里，不引入模板语法）。
- `LocaleProvider` / `useLocale()` / `useMessages(dict)`；非 React 代码用 `messagesFor(dict, locale)`。
- `detectLocale()`、`formatter(locale)` / `useFormat()`：数字、字节、日期时间、相对时间统一走 `Intl`。不要在组件里手写「3 分钟前」「1,234 字节」。
- `describeError(error, locale)`：把 RPC 错误变成当前语言的一句话（见 4）。

各包的词典按包分开，便于并行修改；同一个词在不同包里重复出现可以接受，不做跨包共享词典。

### 4. 后台错误

`ErrorData` 增加可选的 `reason`（稳定的点分小写标识，例如 `skill.name_conflict`）和 `params`（字符串或数字）。

- 后台给**用户在界面上可能看到的**错误加上 `reason` 与 `params`，`message` 用英文作为 Agent、CLI 与日志的兜底；词典中的中文沿用已批准的原文。
- 文案集中在 `packages/ui-kit/src/error-messages.ts`：`reasons` 按 reason，`codes` 按错误码兜底。
- `describeError` 的顺序：有 reason 且词典里有 → 按语言翻译；中文界面 → 原样显示 message；英文界面且 message 是中文 → 显示按错误码的通用说明；否则显示 message。
- Agent 工具返回的业务错误也携带 `reason`，保留原有错误码、冲突、额度与其他结构化信息。只有 `VisError.of` 工厂内部直接调用构造器。
- `SkillProblem` 的 `error` 是英文兜底，`reason?`、`params?` 用于列表问题与导入跳过原因；界面把它们包装为 `describeError` 的 `{ message, data: { reason, params } }` 输入。名称重复与扫描深度通过参数传递。
- 回合启动、引用解析与发送失败通知的 payload 携带 `reason`、`params` 与可选的结构化 `cause`；界面先翻译原因，再插入通知，避免存入转录记录时丢失本地化信息。额度错误进入通知时也保留原有 `reason` 与 `params`。
- 尚只有字符串字段的目录校验、最近删除诊断，以及只有 `{ code, message }` 的生成错误，通过 `describeError` 的显式旧文本映射本地化；映射覆盖 Ark、Mock、Render 与 Agent 发送失败的应用自带文案。已知固定句子与插值进入错误词典；外部服务、文件系统、渲染页的诊断保留原文。后续扩展这些契约时应直接传 `reason` 与 `params`，不再增加旧文本匹配。

### 5. 契约

| 方法 / 类型 | 说明 |
|---|---|
| `preferences.get` `{}` → `{ locale: 'zh-CN' \| 'en' \| null }` | 只允许界面调用；`null` 表示跟随浏览器 |
| `preferences.set` `{ locale }` → `{ locale }` | 只允许界面调用；写 `app.db` 的 `settings` |
| `ErrorData.reason?`、`ErrorData.params?` | 见 4 |
| `SkillProblem.reason?`、`SkillProblem.params?` | 列表问题与导入跳过原因，`error` 保留英文兜底 |

### 6. 防止回退

- `scripts/check-i18n.mjs`（`pnpm check:i18n`）：用 TypeScript AST 扫描界面包里的字符串、模板字符串和 JSX 文本，含中文即报错；注释不算，`messages.ts` 与测试文件不算。确实要保留的字面量在同一行或上一行写 `i18n-exempt` 并说明原因。已并入 `pnpm check`。
- e2e 一律以 `locale: 'zh-CN'` 打开浏览器（契约提交已改），现有按中文 aria-label 和可见文字定位的选择器不变。新增英文 e2e 覆盖切换与各主要界面。
- 错误词典测试扫描后端 reason 字面量与旧文本映射，要求中英都有词条；Windows 与其他平台都检查 zip 校验的全部 reason。

## 不做

- 第三种语言、按项目设语言、RTL。
- 翻译 Agent 提示词、工作消息、CLI 输出、代码注释和 RFC。
- 翻译已有数据，或把存储的类别改成枚举。

## 验收

- `pnpm check`（含 `check:i18n`）通过；`pnpm build` 后完整 e2e 连续两轮通过。
- 单元测试：`detectLocale`、词典取值、`formatter`、`describeError` 各分支；`preferences.get/set` 的默认值与持久化、拒绝 Agent 调用；带 reason 的错误经 gateway 原样到达 `error.data`。
- e2e（英文）：首次以英文浏览器打开即为英文；在设置里切到中文后立即生效并在刷新后保留，切回「跟随系统」恢复英文；画布、会话、看板、设置、Skill 管理在英文下没有中文界面文字（断言可见区域与 aria-label）；一条带 reason 的后台错误在英文下显示英文。
- 中英各一组截图（1600×1000，deviceScaleFactor 2，放 `/tmp`）供维护者过目。
- 两份 README（中英）与路线图更新；`AGENTS.md` 的代码风格改为「界面文案进 messages.ts，中英两份同时写」。
