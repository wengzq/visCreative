# 0020 · 界面打磨（第二批）：统一弹层与图标、卡片减框、节点按素材比例

状态：已实现（2026-10-30）

日期：2026-10-30

接续 [0019](0019-ui-polish-batch1.md)。改版前截图沿用 0019 改版后的 `/tmp/vis-ui-review/after/`。

## 背景

第一批解决了「吵」和「没有主色」。剩下的问题是「同一类东西长得不一样」：

- 8 个对话框用了 6 种遮罩（`#0008`、`#0009` 加模糊、`rgb(0 0 0 / 55%)`、`rgba(0,0,0,.5)`、`--vis-minimap-mask`、透明），有的弹出层也压暗了整页。
- 关闭按钮、展开箭头用文字字符（`×` `✕` `▾` `▸` `▶`），分散在 14 个组件里，大小和基线各不相同。
- 会话列表和看板卡片是框里套框，还有一个不表达任何状态的灰点。
- 生成结果写回已有节点时，节点不跟素材比例走：方形图片节点放进 16:9 的结果，靠 `object-fit: cover` 裁掉了一大块。

## 决定

### 1. 弹层分两类，样式统一

| 类 | 例子 | 遮罩 | 关闭 |
|---|---|---|---|
| 对话框（模态，要做决定或填表） | 设置、新建工作、新建项目、Skill 管理、确认删除、快捷键 | 统一 `--vis-scrim: rgb(0 0 0 / 55%)`，不加模糊 | 右上角关闭按钮、Esc、点遮罩（有未保存输入时点遮罩不关） |
| 浮层（非模态，看一眼就走） | 通知收件箱、今日用量、卡片菜单、项目菜单、@ 选择器 | 无遮罩，只有阴影 | Esc、点外面 |

- `ui-kit/theme.css` 新增 `--vis-scrim`，以及共享的 `dialog.vis-dialog` 外壳（圆角 12、`--vis-panel` 底、`--vis-shadow`、标题行 + 内容 + 底部按钮行，内边距 20/24）。各包删掉自己的 `::backdrop` 和外壳写法，只保留尺寸。
- 今日用量从对话框改成浮层（0019 已改成图标按钮，点开就近显示）。
- 出现动画只用透明度 120ms；`prefers-reduced-motion` 下没有动画。

### 2. 图标统一

`@vis/ui-kit` 新增 `icons.tsx`，里面是内联 SVG 组件，16px，`stroke: currentColor`，线宽 1.5：

- `CloseIcon`、`ChevronDownIcon`、`ChevronRightIcon`、`PlayIcon`；
- `RunningIcon`：顶栏「运行中」不再用播放三角（看起来像「点了开始播放」）；改成三点脉动或旋转弧线，运行数为 0 时是静止的灰色；
- `IconButton`：方形 28px，透明底，悬停时 `--vis-node` 底，必须传 `aria-label`（类型上强制）。

14 处文字字符全部换掉。e2e 按 `aria-label` 定位的不受影响；按字符定位的改成按 `aria-label` 定位。

### 3. 设置导航

设置左侧从平铺按钮改成分组列表：

- **通用**：语言、外观（占位，亮色主题以后做）、安全与额度（只有一项，不单独成组；维护者 2026-10-30 确认）；
- **生成服务**：各服务商，每项右侧有状态点（已配置是绿色，未配置是灰色）；
- **数据**：最近删除。

当前项用 `--vis-accent-soft` 底和主色文字；分组标题是小号 `--vis-text-faint` 大写字母。

### 4. 卡片减框

- 会话列表项与看板卡片只保留一层：卡片本身有 `--vis-node` 底和细边框，内部元素不再各自加框。
- 删除会话列表与看板卡片上不表达状态的灰点。状态点只在有意义时出现：运行中（主色脉动）、需要处理（警告色）、出错（危险色）。
- 看板「已固定」区：去掉虚线大框，改成列顶的一行「已固定」小标题加卡片；没有固定项时整块不显示；拖动卡片时在列顶临时出现一条「拖到这里固定」的放置区，保留拖入固定的入口。

### 5. 节点按素材比例（后端）

素材写进已有节点时，由后端顺带调整节点尺寸。这样 Agent 和异步生成写回时都不会给用户插入撤销步骤（`canvas.apply` 只为 `actor.kind === 'user'` 记录撤销）。

- **触发**：
  - 生成结果交付到已有节点的 `main` 槽位（`deliverOutput` 的 slot 分支）；
  - 以 Agent 身份执行 `slot.setAsset`；
  - 用户自己执行 `slot.setAsset`，例如恢复历史版本。这时调整和换素材在同一个操作里，撤销时一起还原。
- 新建节点（上传、`new_node` 交付）已经按素材尺寸建，不变。`node.create` 带素材但没给 `h` 时，同样按素材比例算高度（实现时发现原来用的是默认尺寸，一并修正）。
- 默认尺寸里媒体节点的短边至少 80px：极窄或极扁的素材原来会建出几像素宽、点不中的节点，内容靠 `object-fit: cover` 裁切。
- **规则**：宽度不变，高度 = `round(w × height / width)`，并夹在 `[80, 4 × w]` 之间。只对图片、视频节点生效，音频和文本不变。素材缺宽高信息时不调整。比例已一致（高度差不超过 2px）时不写。
- **事件**：沿用 `node.updated`，`layoutRevision + 1`。和槽位写入在同一事务、同一 `operationId` 里，界面不用改就能收到新尺寸。
- **重叠**：变高后可能压住下面的节点。按 0016 的约定，Agent 写入时避开重叠，用户手动布局不受干预。这里只调整高度，不移动其他节点。框内成员变高时，沿用框自动撑大的现有逻辑。
- **协议**：方法签名不变，只改语义。`canvas.apply` 和 `generation` 的文档注释写明「写入媒体素材会把节点高度调整到素材比例」。Agent 提示词（`prompt.ts`）加一句，说明这件事不需要它再调 `node.layout`。
- 0019 的「按素材比例调整」菜单项保留，用于旧节点和用户手动拉过的节点。

**手动改过尺寸的节点**：维护者 2026-10-30 选定每次都调整。内容换了，框就跟着走，宽度保留。不新增「锁定尺寸」字段；想要别的高度，生成后再手动拉。

## 实现时的补充

- 点遮罩关闭：`WorkDialog` 增加 `hasUnsavedInput`，调用方传入「有输入或正在提交」的状态，为真时点遮罩不关。
- 收件箱和运行槽位用原生 popover，卡片菜单不再用 `showModal`。
- `IconButton` 的悬停提示是 `title ?? label`，保留调用方带快捷键的提示；`aria-label` 固定为 `label`。
- 设置里的「护栏」改名为「安全与额度」。
- 看板：去掉底部常驻的操作提示（拖动时出现的放置区和卡片菜单「移到…」已经说明）；列不再描边，只靠浅底色区分，拖动时的可放置 / 悬停状态仍显示边框。

## 不做

- 亮色主题。
- 画布节点自动避让（整理功能已有）。
