## 1. 布局

保留现在的两栏结构，不加第三栏：

```
┌ 顶栏：项目名 · 状态 · 今日用量 · 运行中 5/6 · 🔔 收件箱 · ⚙ ┐
├──────────────── 主区域 ─────────────────┬──── 右侧面板 ────┤
│        当前项目 [画布|看板]（悬浮）       │  工作区列表       │
│  画布（普通框）或看板                    │  或单个会话       │
└──────────────────────────────────────────┴──────────────────┘
```

- **右侧面板**：只有列表与会话两种状态，唯一的 `openSessionId` 决定显示哪种。宽度、收起和拖动调宽保留，项目切换器位于列表头部。
- **主区域**：项目名与「画布 | 看板」分段按钮悬浮于画布上方正中，切到看板仍在同一位置。快捷键 ⌘/Ctrl+Shift+B 保留；切换不卸载画布，视口保留，当前视图存 localStorage `vis.main.view`。
- **审阅抽屉**：从右侧滑出，盖住右侧面板（不挤压主区域），宽 480，Esc 关闭。
- **收件箱**：铃铛下方的弹出层，宽 420，最高 70vh，内部滚动。

## 2. 顶栏

| 元素 | 规格 |
|---|---|
| 运行名额 | `运行中 5/6`，悬停解释「同时运行的 Agent 上限 6，满了会排队」；满额转橙色，点击打开名额弹层（见 §7） |
| 铃铛 | 角标显示全部项目的 `unread`；`unread` 为 0 但 `unresolved` > 0 时显示橙色小圆点。`aria-label="收件箱，N 条未读，M 条等待回复"` |
| 项目切换器 | 其他项目有 `unresolved` > 0 时，在切换器按钮和下拉项上显示橙点 |

名额和收件箱计数来自 `events.workSlotsChanged` / `events.workInboxChanged`。连接建立和重连后，先调用一次 `work.slots` / `work.inbox` 取初值。

## 3. 工作区列表与会话（右侧面板）

### 3.1 列表卡片

顶部保留项目切换、「＋ 新建」和搜索，去掉统计行；资产库入口进入项目切换菜单。卡片显示状态点、标题、状态标签、未读数、`⋯`，下面只有一行动作或等待摘要。不显示目录行、角色、Agent 行折叠、框计数或建框按钮。目录、固定、重命名、审阅人和删除统一收进菜单；审阅人文案为「我 / 上级」（子项才可选上级）。

子项缩进 16px；超过 3 个时折叠成「N 子工作项（M 已完成）⌄」，预览最活跃的 3 个未完成项，再显示「还有 N 个」。活跃度排序：等你回复、运行中、待审阅、排队、其余进行中、待办；同级按最近活动时间倒序。已完成项（含子项，显示父标题）收进底部「已完成 N」。

单击卡片进入主会话，即未归档会话里按 `createdAt`、ID 升序的第一个；还没有会话的待办先选择 Agent 并激活。卡片高亮从 `openSessionId` 推出，不单独维护选中卡片；单击卡片和选中画框互不联动，不自动定位画布。搜索仍按标题和目录名过滤，命中子项保留父项。

### 3.2 会话

头部第一行是返回列表、工作区标题和与卡片相同的 `⋯` 菜单；第二行显示状态与 Agent 名。同工作区多个会话用 Agent 标签切换 `openSessionId`（同名依次编号），一个时为静态文字。有改动时显示「在画布中定位」，待审阅时显示「审阅」。

正文为对话记录，底部输入框的引用、Skill 和发送都作用于 `openSessionId`；列表没有输入框。运行中且输入为空时发送按钮变为「■ 停止」；输入内容后恢复发送，排到当前回合之后，并提示「本回合结束后发出」。去掉旧手风琴、面板 `expandedId` / `expandRequest` 和画布选中联动。

面板收起时，只显示正在运行或等你回复的工作区头像；点击展开并进入该项主会话。

### 3.3 新建

「＋ 新建」沿用工作区对话框，调用 `work.create`，带 `chat: { agentKind }` 建会话并申请激活；不再有角色选项或「允许派发」复选框。根项会话天然可以派发一层子项。名额满时提示「名额已满，已排队，空出名额后自动开始」。

## 4. 看板

### 4.1 结构

- 标题区：「工作看板」，下方是项目名。右侧是范围切换「当前项目 | 全部项目」，再往右是 `运行中 5/6 · 全局`。
- **全部项目**时，范围切换下方出现项目筛选 chip（全部 / 各项目），可多选。卡片使用紧凑模式：带项目名标签，不显示缩略图和父级行。
- 「已固定」行：横向排列小卡片（圆点 + 标题 + 状态标签 + ×）。没有固定项时显示虚线框「拖到这里固定，不改变状态」。
- 四列：待办、进行中、待审阅、已完成。列头是圆点、列名和数量。只有待办列有「+」。
- 已完成列只显示最近 7 天，底部「更早的 N 项」点开后展开。

### 4.2 卡片（看板版）

看板卡片保留以下信息量；侧栏使用 0010 的简化卡片：

- **父级行**：`↳ 父标题`，只出现在子项上。
- **缩略图**：最多 2 张，取 `work.changes` 按 `lastSeq` 降序的最近图片或视频节点当前素材，每节点只选一次，不按框过滤。只在当前项目显示，全部项目视图不显示。
- **等待行**：`waitingOn` 不为空时显示，橙色，`等待回复 · {excerpt}`。`excerpt` 由服务端去掉 Markdown 标记、折成一行。点击打开收件箱，并定位到这条消息。
- **审阅提示**：待审阅的卡片显示「完成报告已就绪 · N 处产物变更」（N 取 `WorkItemView.changeCount`，按节点去重）。用户送审、没有报告时显示「没有完成报告」。
- **打回后排队，接着上一轮改**：`pendingFeedback` 为真时显示，灰色（名额满时打回，排到后保留本轮审阅基线）。
- **底部**：左边 `今日生成 N`，右边在有改动时显示 `本轮改动 N 处`（`changeCount`），没有改动则省略。

卡片悬停时显示快捷按钮，最多 3 个，按状态给：

| 状态 | 按钮 |
|---|---|
| 待办 | 激活（排队中时为「取消排队」） |
| 进行中 | 打开会话、在画布中定位、回收 |
| 待审阅 | 审阅、在画布中定位 |
| 已完成 | 在画布中定位、重开 |

`⋯` 菜单与侧栏卡片相同。没有本轮改动时隐藏所有「在画布中定位」入口；有改动时定位到本轮改过的节点，缩放到包住它们的范围并选中。单击待审阅卡片打开审阅抽屉；其余进入主会话并切到画布。

### 4.3 拖动

用指针事件实现，不用 HTML5 拖放，这样触控板和测试都稳定。

- 拖起后卡片半透明并跟随指针，四列都高亮。
- **看板是用户的**：任意两列之间都能拖，不拦截、不回弹、不要求填理由，也不弹确认框。放下即调用 `work.move({ status })`。唯一的例外是还没有会话的待办拖到进行中：先弹「选择 Agent」（Codex / DeepSeek），子项默认 Codex，再 `work.activate`。

| 从 → 到 | `work.move` 的效果 |
|---|---|
| 待办 → 进行中 | 同激活：建或恢复会话，投递 brief；满额时排队 |
| 待审阅 → 进行中 | 退回，保留审阅基线，**不发消息**，Agent 等用户在会话里开口或在抽屉里写意见 |
| 已完成 → 进行中 | 同重开，不附说明 |
| 任意 → 待办 / 待审阅 / 已完成 | 只改状态，清掉排队标记和本轮报告；离开进行中时释放名额。拖到已完成时归档会话，同送审、通过一样不要求子项先完成 |
| 任意 → 已固定行 | `work.update pinned: true`，状态不变 |

拖动**不打断任何人**：不停止当前回合、不取消生成、不级联子工作项。离开进行中后会话队列暂停，当前这一步跑完就停，不再开新回合，重新激活时恢复。卡片移出进行中时如果还有回合或生成在跑，toast 提醒：「『{标题}』的任务还在运行，会继续跑完当前这一步；要立刻停下，请在会话里停止」。真要停下用菜单里的「回收」。

- **全部项目视图**：拖动和按钮直接带卡片的 `spaceId` 操作，不切换项目。只有「审阅」和「在画布中定位」会先切项目。
- **键盘**：卡片可以聚焦（Tab），Enter 等于单击。⋯ 菜单里的「移到…」子菜单列出其他三个状态，作为拖动的替代。

### 4.4 空状态

- 看板没有任何工作项时：「还没有工作项。点待办列的 + 新建，或在根工作区的会话里让 Agent 派发。」
- 单列为空时，列内显示淡色的「暂无」。

## 5. 对话框与确认

统一沿用现有的对话框样式（`QuotaConfirmation` 那套）。

### 5.1 新建待办（看板 +）

字段：
- 标题（必填，60 字）。
- 任务说明（Markdown 文本框，可选）。
- 父工作项：可选，下拉列出当前项目的根工作项。

选了父项就调用 `work.dispatch`（`activate: false`），否则调用 `work.create`。

### 5.2 改状态不确认

回收、重开、拖动换列都直接执行，不弹确认框，也不要求理由（参照 Orca：看板是用户自己的）。会停下 Agent 的只有回收和删除（停止回合、取消生成、父项级联）；删除不可逆，是唯一要确认的操作，见 §5.5。菜单里的「打回」打开一个意见框，意见可选：不写只退回进行中，写了作为 `review_feedback` 发给 Agent，按钮文案随之从「打回」变为「打回并发送意见」。

回收后，结果里有 `providerCancelled: false` 的任务时，追加一条 toast：「N 个生成任务已在服务端开始，可能仍会计费」。

### 5.3 状态操作的文案

| 操作 | 按钮文案 | 成功提示 |
|---|---|---|
| activate | 激活 | 排队时：「名额已满，已排队（第 N 位）」 |
| recall（排队中） | 取消排队 | — |
| submitReview | 送审 | — |
| review approve | 通过 | — |
| review reject | 打回 | 排队时：「名额已满，已排队，意见会在开始时送达」 |
| reopen | 重开 | 同 activate |

### 5.4 错误映射

| 错误码 | 界面表现 |
|---|---|
| `invalid_transition` | toast：「当前状态是 {状态}，不能 {操作}」（只在卡片已过期时出现，例如菜单操作时状态已被别人改掉） |
| `revision_conflict` | 静默刷新卡片，并 toast「卡片已被修改，已刷新」 |
| `already_resolved` | 见 §8 |
| `forbidden` / 其他 | 沿用现有的 `fail()` 提示 |

### 5.5 删除确认

菜单「删除…」打开确认框，打开时调用一次 `work.deletePlan` 取计数，读取期间按钮禁用。

```
删除「镜头 2 · 街角霓虹」？

⚠ Agent 正在工作，删除会先停止它
⚠ 2 个生成任务未完成，取消后服务端可能仍会计费
⚠ 包含 3 个子工作项（1 个进行中），会一起删除
⚠ 有 1 条提问在等你回复，删除后不再处理
⚠ 完成报告还没审阅

会话会归档，工作目录保留：~/…/workspaces/镜头 2

                         [取消]  [停止并删除]
```

提醒逐条按条件出现，计数包含子工作项：

| 条件 | 提醒 |
|---|---|
| 有进行中的回合 | Agent 正在工作，删除会先停止它 |
| 有未结束的生成任务 | N 个生成任务未完成，取消后服务端可能仍会计费 |
| 有子工作项 | 包含 N 个子工作项（M 个进行中），会一起删除；没有进行中的省略括号 |
| 有未解决的提问 / 阻塞 / 升级 | 有 N 条提问在等你回复，删除后不再处理 |
| 待审阅且有完成报告 | 完成报告还没审阅 |
| 排队中 | 正在排队，删除会取消排队 |

- 一条提醒都没有时，正文只有「会话会归档，画布内容保留。」和目录路径。
- 有进行中的回合或未结束的生成时，主按钮是「停止并删除」，否则是「删除」；红色（`--danger`）。默认焦点在「取消」，Esc 关闭。
- 画布内容和工作目录始终保留，不提供画布删除选项。
- 成功后关闭确认框；如果审阅抽屉或会话记录正打开着这个工作项（或它的子项），一并关闭。toast「已删除「{标题}」」，结果里有 `providerCancelled: false` 的任务时追加 §5.2 的计费提示。不提供撤销。
- 全部项目视图里直接带 `spaceId` 删除，不切换项目。

## 6. 画布上的框

### 6.1 渲染

- 框是普通画布节点，永远在内容节点下面；1px 主题色边框、透明填充与圆角沿用现有样式。
- 标题栏只显示框标题，不显示工作项状态、Agent 头像或写入权限提示。缩放小于 0.35 时保留固定屏幕字号。

### 6.2 交互

- 只有标题栏可抓取，整体拖动使用 `frame.move`，递归移动成员并作为一步撤销；框尺寸变化不移动内容，服务端重算归属。
- 框空白区域对指针透明；双击画布空白不新建文本，节点只由底部工具栏和文件导入创建。双击文本编辑、媒体预览保留。
- 点击标题栏只选中框，不选择工作区、不切换会话面板。删除框保留成员，不涉及工作项解绑或授权提示。
- 复制、粘贴、创建副本仍跳过框；框内生成中边框高亮沿用现有样式，不加动画。
- 不再提供「为工作项画框」或 `work.update({ frame })`。

## 7. 名额弹层

```
运行中 5/6 · 全局                    [调整上限]
艾莲换装短片  4    城市夜景 MV  1/2   ← 项目上限不为空时显示 used/limit
等待空位
 1. 城市夜景 MV › 片尾 · 城市字幕   3 分钟前   [取消排队]
```

「调整上限」打开生成服务设置的「护栏」分组，在现有每日上限下面新增：
- 同时运行上限：步进器，1–32。
- 各项目上限：每个项目一行，「不限」或数字。

这两项调用 `work.setSlotLimit`。

## 8. 收件箱

### 8.1 内容与已读

- **分组**：按「项目 › 工作项」两级。项目名是小标题；工作项一行显示标题、状态标签和父标题。
- **消息**：每条消息包含：
  - 种类标签：提问 / 阻塞 / 升级 / 完成；
  - 来源：`Codex · 工作区标题`；
  - 正文，用 react-markdown，不允许原始 HTML，超过 6 行折叠；
  - 关联节点 chip，显示节点名（`work.inbox` 的 `nodeLabels`：框标题、文本首行、媒体类型加提示词首行，已删除时为「已删除的节点」），点击会先切项目再定位；
  - 相对时间。
- **未解决的提问 / 阻塞 / 升级**：下面有回复框，⌘/Ctrl+Enter 发送，Enter 换行。
- **完成报告**：带「审阅」按钮，点击打开审阅抽屉。
- **已读**：打开收件箱时，对当前可见的每个工作项调用 `work.markRead`。角标随之清零，橙色等待状态保留。

### 8.2 处理后的条目

本次打开期间，处理掉的条目留在原位，显示结果：
- 「已由你回复」，带回复正文的摘要。
- 收到 `already_resolved` 时：显示「上级已先回复：」和首次回复。你的输入保留在框里，下面有两个按钮：「改为追加说明」（不带 `replyTo` 重新发送）和「放弃」。

关闭收件箱后再打开，只显示未读或未解决的条目。

**空状态**：「没有需要你处理的消息」。

## 9. 审阅抽屉

依次包含：

1. **头部**：工作项标题、项目名、`审阅人：我 / 上级`、关闭按钮。
2. **完成报告**：最新一条 `done` 消息，用 Markdown 渲染。用户送审时显示提示框「没有完成报告」。
3. **产物变更**：来自当前激活基线后该工作区自身会话的 `work.changes`，按 `lastSeq` 降序。
   - 每条变更显示节点类型图标、标题（文本取首行，媒体取类型）、变更类型标签（新增 / 修改 / 删除），以及前后对比：媒体用两张缩略图，文本用前后两段并排。前后修订通过 `slot.history` 读取。
   - 点击一条变更，画布定位到对应节点，抽屉不关闭。
4. **消息历史**：`work.get` 分页，按时间正序，可折叠。
5. **底部固定**：
   - 「打回」：展开意见输入框，可选。空着时确认按钮是「打回」，只退回进行中；写了意见是「打回并发送意见」。
   - 「通过」：主按钮。
   - 父项还有未完成的子项时只列出提示，按钮照常可用。

## 10. vis 工具确认

所有会话（包括未关联工作项的会话）的 vis 工具确认自动通过，不显示框外审批卡。`canvas_outside_frame` 类型删除；迁移将旧 pending 记录过期，对应回合按拒绝处理。其他命令和文件审批保留现有行为，网关继续执行调用方、工作区关系、修订号及费用护栏检查。

## 11. 实时同步

- `work.itemChanged`：整卡替换，按 `revision` 丢弃旧版本。
- `work.messageAdded`：更新卡片的未读数、未解决数和 `waitingOn`。卡片视图会随 itemChanged 一起到达，界面以卡片视图为准，消息事件只用于刷新打开中的抽屉和收件箱。
- 全局事件只更新计数。收件箱打开时收到 `events.workInboxChanged`，重新调用一次 `work.inbox`，同时合并本次打开期间已处理的条目。

## 12. 通用

- **相对时间**：刚刚（<1 分钟）、N 分钟前、N 小时前、昨天、M 月 D 日。
- **动画**：所有过渡尊重 `prefers-reduced-motion`。拖动回弹、抽屉滑入、画布定位在减少动画时都改为直接切换。
- **无障碍**：
  - 看板的列用 `role="list"`，卡片用 `role="listitem"`，卡片的 `aria-label` 包含标题、状态和等待情况。
  - 弹层和抽屉要把焦点困在内部，Esc 关闭，关闭后焦点回到触发元素。
- **配色**：只用现有的暗色主题变量，新增颜色写进 `app.css` 的变量里。不引入图标库，图标都是内联 SVG。
- **e2e 选择器**：用 `aria-label` 或文案，不用 `data-testid`。
